# Deeplink 与悬浮录制设计

## 阶段边界

悬浮窗只属于点击录制阶段，不参与测试或实际规则执行。录制流程为：编辑点击动作 → 使用规则中最近的前置 deeplink（没有时使用默认 deeplink）打开目标应用 → 无障碍覆盖层显示“开始录制” → 用户点击开始 → 用户手动点击目标控件 → 保存控件特征、相对坐标和从开始到点击的延迟。

本改造不拆分正式包与调试包，不修改 `applicationId`，也不新增独立签名方案；安装升级继续沿用项目当前应用身份与既有开发签名。

测试运行与正式执行继续沿用已保存的点击动作：打开 deeplink 后按已记录延迟自动查找并点击，不显示录制悬浮窗，不等待用户确认。

## 状态与安全

点击记录状态增加“等待开始”。打开 deeplink 时只准备录制，不捕获任何点击。无障碍服务忽略 AutoJump 自己、桌面、锁屏、权限页和系统选择器；首次出现的合格目标应用会绑定为本次录制包名，并显示 `TYPE_ACCESSIBILITY_OVERLAY` 覆盖层。用户点击覆盖层后才进入“已开始记录”，覆盖层立即消失。

开始按钮自身不会被当成目标：录制状态绑定的是底层目标包，覆盖层属于 AutoJump 包。开始后切到其他应用、点击密码框或系统界面会拒绝本次记录。录制五分钟后自动过期，悬浮窗提供取消入口。

## Deeplink 来源

点击编辑器显示可编辑的“录制跳转 deeplink”。编辑已有动作时，规则编辑器向前查找最近的 deeplink 动作；新增点击时查找动作列表末尾之前的最近 deeplink；均未找到时使用手机当前默认值：

`example://page/path`

该值只用于预填和跳转，用户仍可在录制前修改。
