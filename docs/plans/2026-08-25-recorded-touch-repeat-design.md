# 真实触摸重复回放设计

## 目标

一次真实触摸录制可以在正式执行时独立回放多次，并配置两次手势之间的间隔。当前飞书打卡规则使用 2 次、间隔 800ms。

## 方案

不把两次点击拼成一次长按轨迹，而是在同一个 `RECORDED_TOUCH` 动作中保存 `repeatCount` 和 `repeatIntervalMs`。每次仍是完整、独立的 DOWN/MOVE/UP 手势；上一轮系统确认完成后等待指定间隔，再派发下一轮。旧规则缺少字段时按 1 次、800ms 读取，因此 schema v4 保持兼容。

编辑页提供“正式回放次数”和“两次间隔”两个参数。次数限制为 1–5，间隔限制为 50–10000ms，避免误配置造成快速连点或长时间占用。只有全部手势均被 Android 接受后动作才完成；任意一次取消或拒绝都按原失败策略处理。

## 验证

- 模型测试覆盖默认值、2 次配置、JSON 往返和边界校验。
- 全量 JVM 测试、Android Lint 和 APK 构建通过。
- 小米 14 Pro 真机将 67ms、2 点轨迹设为 2 次、间隔 800ms；2026-08-25 16:37 完整执行 deeplink 和双次回放后，飞书考勤页明确显示“打卡成功”。应用日志同时记录“真实触摸轨迹已发送（67ms，2点，2次）”及规则执行完成。
