# Material UI 刷新设计

## 目标与入口边界

界面直接采用项目已依赖的 Material Components 1.11，不引入额外 UI 框架或外部模板。桌面图标普通点击保持现有自动化语义：立即匹配并执行规则；没有启用规则时打开默认 deeplink。普通点击不展示管理页面。长按桌面图标选择“设置”时进入规则管理首页。

长按入口继续使用 Android 静态快捷方式，保证安装后即可用。应用每次普通启动时刷新旧版动态 deeplink 快捷项，并清除历史上可能残留的重复“设置”动态项；静态“设置”始终保留。快捷入口只负责路由，不改变规则执行和默认 deeplink 逻辑。

## 视觉系统

整体使用 Material 的浅色工具型界面：暖灰页面背景、靛青主色、白色圆角卡片、深色正文和低饱和辅助文字。主操作使用填充按钮，测试、编辑等次操作使用描边或文字按钮，删除与停止操作使用危险色。控件最小触摸区域保持 48dp，正文和状态色满足清晰对比，布局允许系统大字体自然换行。

管理首页使用 MaterialToolbar、概览卡、规则卡和空状态。概览卡展示规则总数、启用数量及无障碍自动点击状态；“新增规则”为主按钮，“测试运行”为次按钮。规则卡突出名称、开关和优先级，并分层展示条件与动作摘要。导入、导出、权限状态和关于继续通过顶部菜单访问。

规则编辑、点击动作和权限状态页复用相同的卡片、标题、输入框和按钮样式。此次只调整信息层级、组件和文案呈现，不修改规则模型、录制状态机、自动点击、安全解锁或数据格式。

## 状态与验收

首页必须覆盖有规则、无规则、全部停用以及无障碍服务开关状态。列表刷新、启用开关、编辑、删除、测试运行、导入导出均保持可用。点击动作页的录制 deeplink、延迟与选择器字段完整保留；权限页所有原按钮 ID 保留，避免业务代码断裂。

构建验收包括 36 项现有单元测试、Android Lint、Debug APK 编译、快捷方式清单检查，以及真机截图对比。真机未连接时先交付可安装 APK，设备恢复后补做桌面普通点击、长按“设置”和管理首页大字体检查。
