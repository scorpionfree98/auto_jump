# AutoJump 完整重构与延迟点击设计

## 目标与范围

本轮重构先交付一条可验证的自动化主链路：用户配置规则，规则匹配后打开 deeplink，并在目标应用出现后按配置等待，再通过 Android 无障碍服务执行一次或多次确定性的点击。点击优先使用控件 ID、文字或无障碍描述定位，找不到控件时才使用相对屏幕坐标。用户可以开启“录制下一次点击”，由无障碍事件提取目标应用、控件特征和坐标，生成可编辑的点击动作。

自动解锁不在本轮实现。架构会保留 `DeviceGate` 边界，后续可接入“唤醒屏幕、请求系统认证、解锁后续跑”，但不会采集、保存或重放 PIN、图案和密码，也不会通过无障碍服务绕过系统安全控制。

## 架构

项目继续使用 Java、Android Views、AndroidX 和 Gson，避免在修复核心可靠性问题的同时引入 Kotlin/Compose 迁移风险。代码按职责拆分为：

- `domain`：规则、条件、动作和执行结果等纯数据模型。
- `data`：版本化 JSON、SharedPreferences 存储和旧数据迁移。
- `engine`：条件评估、规则排序和动作编排，不直接依赖界面。
- `automation`：待执行会话、deeplink 启动、无障碍点击和录制。
- `ui`：规则列表、规则编辑、点击动作编辑和权限引导。

规则文件使用带 `schemaVersion` 的文档封装。条件和动作都使用显式枚举类型，避免 Gson 反序列化抽象类失败。动作统一建模为 `DEEPLINK`、`WAIT`、`CLICK`；每个动作都有执行顺序和错误策略。旧版字符串 deeplink 与可推断类型的旧条件在首次读取时迁移，新写入数据只使用新格式。

## 执行数据流

`MainActivity` 首先识别明确入口：设置、桌面快捷 deeplink 或规则运行。规则运行由 `RuleEngine` 返回匹配结果，`AutomationOrchestrator` 创建带唯一 ID 的执行会话并顺序处理动作。deeplink 动作直接启动目标应用；等待和点击动作写入 `PendingExecutionStore`，由无障碍服务在目标包窗口出现后继续。

点击动作包含目标包、延迟、超时、重试间隔、选择器和坐标回退。无障碍服务只处理当前有效会话，先校验目标包，再按 viewId、文字、contentDescription 搜索节点并点击最近的可点击父节点。超时前可以重试；若仍未找到且配置了相对坐标，则通过 `dispatchGesture` 点击。成功、失败、取消和超时都会写入本地执行日志，并推进或终止会话。

录制模式必须由用户在应用内显式启动，且一次只捕获下一次点击。服务收到 `TYPE_VIEW_CLICKED` 后保存包名、控件特征和屏幕边界，立即退出录制模式。密码输入框、系统锁屏和标记为敏感的节点不录制；默认不保存截图或页面文本全文。

## 安全、错误处理与发布约束

无障碍能力启用前显示独立用途说明并取得确认，设置页提供服务状态、停止执行和清空日志入口。自动化仅执行用户保存的静态动作，不根据页面内容自主规划，不跨目标包点击，不在锁屏界面执行。目标应用不匹配、页面超时、节点不可用、deeplink 无处理程序或服务未开启时，均产生可读错误而不是静默失败。

若发布到 Google Play，需要完成 AccessibilityService 声明、演示视频、显著披露和隐私政策；本地侧载构建也保留相同的披露和停止能力。

## 验收标准

1. 带任意条件和动作的规则保存、重启、导入和导出后保持一致。
2. 桌面快捷方式能执行其指定 deeplink，不再误走规则引擎。
3. 跳转到目标应用后，点击动作按延迟执行，并支持控件选择器与相对坐标回退。
4. 录制模式只记录下一次非敏感点击，并能生成可编辑动作。
5. 无障碍服务关闭、目标页面超时或链接不可用时有明确日志和提示。
6. 核心模型、迁移、条件匹配和动作队列有单元测试，项目能在 120 服务器的 Docker 环境编译。
