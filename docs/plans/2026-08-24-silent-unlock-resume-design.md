# 静默解锁续跑设计

## 目标

锁屏规则不再显示 AutoJump 自己的“等待系统解锁 / 重试 / 暂不执行”页面。应用只唤醒屏幕并直接请求 Android 系统认证；认证取消后任务静默等待，用户之后解锁设备时自动从原会话继续。同一规则已有未完成会话时不得重复入队。

## 方案比较

1. **透明系统认证跳板 + 持久会话轮询（采用）**：保留透明 `UnlockGateActivity`，直接调用 `requestDismissKeyguard`。无障碍服务已有锁屏期间定时检查能力，解锁后可继续原会话。改动集中，仍遵守 Android 安全边界。
2. **通知引导用户解锁**：后台限制更少，但多一步点击，和“去掉蠢弹窗”的目标不符。
3. **录制并模拟 PIN/图案**：安全锁屏限制无障碍访问，且必须保存认证凭据；不可靠也不安全，不采用。

## 状态流

规则入队前，先按 `ruleId` 查找状态为 `PENDING`、`WAITING` 或 `RUNNING` 的会话。找到时复用原会话；若设备仍锁定且本次是用户再次点击入口，只重新打开透明系统认证跳板，不新增任务。

首次入队且设备锁定时，会话转为 `WAITING`，透明跳板唤醒屏幕并直接请求系统解锁。系统认证成功后调用 `resumeAfterUnlock`；取消或暂时不可用时只写一条等待日志并立即关闭跳板，不显示应用页面。无障碍服务继续保留会话并定时检查；设备后来解锁时直接执行当前动作。

## 验证

- 存储层单元测试覆盖同规则活动会话查询，并排除 `FAILED`、`CANCELLED`、`COMPLETED`。
- 编排层通过活动会话去重，桌面入口重复点击不产生第二个 session ID。
- Android Lint、JVM 测试和 Debug APK 构建全部通过。
- 小米 14 Pro 真机验证：锁屏启动只出现系统锁屏认证；取消后无 AutoJump 页面；解锁后原 session 恢复；重复点击入口不新增会话。
