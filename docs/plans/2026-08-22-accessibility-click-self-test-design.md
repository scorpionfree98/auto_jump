# 无障碍延迟点击自检设计

## 目标

在不操作微信、飞书、系统设置或其他第三方应用的前提下，提供一个可重复的真机验收入口，验证 AutoJump 的执行队列、延迟调度、无障碍控件查找、点击动作和执行日志确实连通。

## 方案选择

考虑过三种方式：点击第三方应用控件最接近真实场景，但容易产生实际业务操作；记录规则页现有按钮改动较少，但按钮通常会打开弹窗，容易遮挡目标并形成递归测试；在权限页加入专用测试控件会多出少量诊断 UI，却能把目标限定在应用自身，结果也最容易判断。因此采用第三种方式。

## 数据流与安全边界

用户点击“开始安全点击测试”后，应用创建一条只存在于执行队列、不写入规则列表的临时规则。规则包含一个点击动作：延迟 1 秒，目标包名固定为 `com.autojump.app`，目标控件固定为专用测试按钮的资源 ID，不配置文本匹配和坐标兜底。无障碍服务按现有生产链路查找并点击控件，成功后写入执行日志并删除完成的会话。

无障碍服务配置显式启用 `flagReportViewIds`，保证 Android 向服务提供控件资源 ID；否则页面检查工具虽然能看到 ID，服务进程中的 `AccessibilityNodeInfo` 仍可能得到空值，精确选择器会一直重试到超时。

页面只有在同时观察到专用目标按钮被点击、且同一会话存在成功执行日志时才显示“测试通过”。服务未开启时不创建任务；超时或执行失败时显示失败原因，并恢复重试按钮。重复开始测试前会清理遗留的自检会话，避免多个测试互相影响。专用测试不会保存为用户规则，也不会访问或点击其他应用。

## 验证

- 单元测试校验临时规则的目标包名、控件 ID、延迟、超时和无坐标兜底约束。
- 远程 Docker 环境执行全部单元测试和 Debug APK 构建。
- 小米 14 Pro / HyperOS 真机开启服务后运行自检，核对页面通过状态、完成日志、空待执行队列和无崩溃日志。
