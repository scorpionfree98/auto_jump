# ADR-003：业务验证独立于输入派发

状态：接受

日期：2026-08-24

## 背景

Android 的手势回调只能说明手势已完成或被取消。目标应用可能接收事件但拒绝业务操作。当前会话在派发完成后推进到 `COMPLETED`，无法回答用户最关心的“是否真正打卡成功”。

## 决策

输入动作完成后必须进入独立的 `VERIFYING` 阶段。只有配置的业务验证器观察到成功证据时，状态才是 `VERIFIED`。飞书首批验证器为成功画面/文案识别及考勤记录变化。超时结果为 `UNVERIFIED`，不得展示为成功。

允许配置一次完整重试：重新打开 Deeplink、等待窗口稳定、回放、验证。禁止在未知页面连续重复坐标点击。

## 后果

- 优点：日志与用户看到的结果真实，能够区分输入失败和业务拒绝。
- 代价：需要截图能力、视觉/文本验证配置及更完整的状态机。
- 风险：视觉提示可能短暂或被遮挡，因此应支持多种验证证据，并保存置信度和时间。

## 被否决方案

- 以 `dispatchGesture.onCompleted()` 作为成功：它不包含目标应用业务状态。
- 只让用户观察：无法自动重试，也无法形成可诊断的执行记录。
