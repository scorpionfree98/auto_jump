# ADR-002：录制并回放真实触摸轨迹

状态：接受

日期：2026-08-24

## 背景

现有“录制”监听 `TYPE_VIEW_CLICKED`，保存节点中心和从开始到点击的总延迟。它没有记录用户的 `DOWN/MOVE/UP` 序列。真机证据显示，飞书目标按钮对瞬时 tap、节点点击和零长度手势没有业务响应，而持续触摸可以成功。

## 决策

用户点击“开始录制”后，使用一次性全屏无障碍触摸覆盖层捕获下一次完整触摸。保存所有必要轨迹点及相对时间，隐藏覆盖层后立即通过无障碍手势原样回放。正式执行同样回放该轨迹，而不是合成固定 160ms 的通用 tap。

坐标相对于应用可用区域归一化，并同时保存显示尺寸、方向、密度、系统栏和应用版本信息。设备配置不能安全换算时停止执行并要求重录。

## 后果

- 优点：复现用户已成功的实际操作，包括落点、持续时间和轻微移动。
- 代价：录制层会消费原始触摸，必须在隐藏后安全回放；轨迹格式和显示变换更复杂。
- 风险：目标应用或 ROM 仍可能区分无障碍合成输入。若真机验证失败，普通 APK 路线应明确判定受限，不能继续假报成功。

## 被否决方案

- 固定 160ms、固定 4px 移动：可以作为诊断实验，但不能代表用户真实手势，也不能泛化到其他控件。
- 只保存手指抬起坐标：缺少影响目标事件处理的持续时间和移动序列。
