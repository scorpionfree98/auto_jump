# ADR-001：分离节点动作与录制触摸动作

状态：接受

日期：2026-08-24

## 背景

当前 `RuleAction.CLICK` 同时携带节点选择器、录制坐标、延迟、重试和超时。录制时从节点矩形中心生成坐标，回放时又可能用实时节点中心覆盖坐标。这使节点识别成为录制回放的隐式前置条件，并造成 WebView、自绘控件和重复文本场景不稳定。

## 决策

schema v3 将点击拆分为：

- `RECORDED_TOUCH`：用户录制的真实触摸轨迹，回放时不由节点候选覆盖；
- `ACCESSIBILITY_NODE`：明确使用 ID、文本或描述查找原生节点并执行语义点击。

旧 `CLICK` 规则迁移策略：有录制坐标的规则迁移为兼容型 `RECORDED_TOUCH` 单点脚本并标记“建议重录”；没有坐标但有选择器的规则迁移为 `ACCESSIBILITY_NODE`。

## 后果

- 优点：两种动作执行语义明确，录制结果成为唯一事实来源，测试可以分别覆盖。
- 代价：需要 schema 迁移、编辑页调整和新轨迹持久化格式。
- 风险：旧坐标没有真实轨迹，只能兼容执行，不能获得新录制的可靠性。

## 被否决方案

- 继续在单一 `CLICK` 上增加优先级和特殊判断：会继续扩大可选字段组合和隐式耦合。
- 全部改成节点动作：无法解决已在飞书 WebView 上复现的语义点击无业务响应。
