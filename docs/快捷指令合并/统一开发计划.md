# 工具合集统一开发计划

更新时间：2026-10-13。本文作为后续开发和验收的主清单；早期 plans 和历史验收记录保留作证据，冲突时以最新用户决策及本文为准。

## 已确定的产品范围

- 正式主仓库 `auto_jump`，应用名称“工具合集”，应用 ID、正式签名和高德模块保持兼容。
- 普通桌面启动执行用户指定的默认指令；长按应用快捷方式提供“自动任务管理”“工具合集入口”及用户选择展示的指令。
- 时间触发由小米系统自动任务负责，应用内部不增加定时器。
- 指令按串行队列执行，轮到任务时检查最新配置及 WiFi 等条件。
- 签到使用固定延迟的录制触摸回放；录制阶段由用户点悬浮窗开始，正式执行无需此步骤。
- 支持最多 8 个录制动作、排序、延迟、重复次数、屏幕比例容差及固定偏移。
- Shizuku 已运行且用户已授权时，辅助自动恢复本应用无障碍服务；手动入口作为兜底。
- 锁屏时唤醒并请求系统认证，解锁后继续。不会保存或回放锁屏密码。
- 手势派发与业务成功分别记录；无业务证据不报签到成功，不无限重试。
- 手机操作暂时暂停。密钥、个人配置、Webhook 和私有备份不进入 Git。

## 明确延期的需求

- 动态选择并定位目标按钮：用户已要求作为待办，当前签到继续使用录制方案。
- 自动业务结果识别：需要另行定义成功证据、识别方式及权限；当前显示“操作已发送，请确认结果”。
- 分身：独立实验，暂不并入正式应用。

## 执行门槛与交付记录

1. 先完成 P0 代码修复和行为测试，再执行构建、Lint、正式签名检查。
2. 用户恢复手机操作授权后，先备份配置，覆盖升级，再从安全测试验证权限恢复与点击链路；真实签到按已有授权及设备状态安排单次可核验测试。
3. 每项验收记录提交 ID、APK SHA-256、设备版本、步骤、预期/实际结果及证据位置。旧版本通过不能自动计入新版本。
4. P0 未关闭时不标记发布通过。测试数量、构建成功、系统接受手势均不能单独代表功能或业务验收。
5. 提交前检查密钥与个人数据；只提交明确属于本任务的文件，保留其他工作区改动。
