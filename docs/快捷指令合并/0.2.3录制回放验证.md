### 17:31 回归根因与修复验收

- 根因已由主线程消息历史确认：URL Scheme 切到飞书后，小米系统会暂停工具合集正在执行的消息。两次失败中，相关消息分别停留 72.664 秒和 49.573 秒；普通 Handler 延迟回调只能在工具合集重新回到前台后继续，因此此前没有按时点击。不是无障碍未授权、坐标未读取或打卡按钮控件识别失败。
- 修复为：当 DEEPLINK 后紧接同一目标包的 RECORDED_TOUCH 时，先把包含固定起始延迟及全部重复次数的 GestureDescription 提交给 Android 无障碍系统，再打开目标链接。工具合集进程切到后台后，系统仍持有并按时执行手势。
- 17:31 真机从 MAIN/LAUNCHER 触发默认指令。系统输入日志记录两次真实触摸，落点均为 805,1422，间隔约 800ms；没有人工或 adb 点击打卡按钮。目标页面截图明确显示 17:31“打卡成功”。
- 正式源码已移除主线程堆栈、Looper 队列及逐行调度诊断；新增回放时间计划的边界/溢出测试。最终 123 项单元测试零失败、零跳过，Release lint 与构建通过。
- 本次证明解锁状态下“默认入口 → URL Scheme → 固定延迟 → 两次录制点击 → 业务成功”。本修复后的锁屏触发、取消预提交手势和长期后台稳定性仍需分别验收，不能由本次结果外推。

### 实现口径

- RECORDED_TOUCH 从动作开始时间（紧接链接启动请求）等待 delayBeforeMs，不等待目标窗口事件、控件树或页面内容稳定。
- 缺失目标应用事件时按已请求跳转的假设继续回放；若新窗口事件明确显示已切换到其他应用，则停止。按事件发生时间判断，迟到的旧桌面事件不作为新切换。
- 保留锁屏、取消、动作期限、方向、屏幕比例和轨迹越界检查；重复点击前再次检查任务和锁屏状态。
- 旧页面稳定等待参数仍可读取/导出，但不再用于此回放模式，编辑页隐藏该旧参数。
- 签到不使用 ACTION_CLICK。历史 CLICK 类型和应用内安全控件测试仍保留兼容，不能用其通过结果代替录制手势验收。
- 此模式不识别按钮是否加载或业务是否成功；缺失窗口事件时不能保证实际显示的就是目标页面。验收必须看目标应用结果。

### 队列运行级测试过程

- API28 x86 模拟器第一次安装失败：正式依赖带 ARM 地图库，INSTALL_FAILED_NO_MATCHING_ABIS。
- 增加 queueRuntimeOnly=true 的隔离 debug 构建，仅排除队列测试不使用的原生库；严格限制任务为 assembleDebug / assembleDebugAndroidTest。显式要求 Release 时已验证构建拒绝。不是正式/调试包分离改造，不影响真机 Release 包。
- 首次执行在“运行中去重”断言失败；复跑容量断言在主线程抛异常导致测试进程退出。这两次保留为失败，不能计入通过。
- 为避免软件模拟器处理开销使短 WAIT 在断言前结束，测试中的首任务/容量任务延长等待，去重断言后主动释放首任务；断言异常转交测试线程，保证进入恢复逻辑。只清理 runtime-test- 前缀的测试遗留队列，不触及其他任务。
- 修订后使用原始 instrumentation 输出复跑：checks_passed=33，checks_skipped=0，stream=PASS 33 checks，INSTRUMENTATION_CODE=-1，命令 exitCode=0。完整运行级检查通过。
- 脚本补充 -r，避免 Android 将 stream 格式化输出时省略结束码而误报失败；保留必须同时出现 PASS 与成功结束码的验收要求。
- 通过范围：FIFO、运行/排队去重、WAIT/排队取消、容量20/停止全部、失败后继续、出队停用/条件变更、条件不满足与 WiFi 无权限、中断恢复、过期期限。取消当前录制手势、多应用真实切换、WiFi 实际满足/不满足、录制签到和锁屏仍未设备验收。
